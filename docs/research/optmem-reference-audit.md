# OptMem and OptChat reference audit

Audited against OptMem commit [`1fb164cf39028047781f72ac3bb1e5a691c1dcb0`](https://github.com/VictorTaelin/OptMem/tree/1fb164cf39028047781f72ac3bb1e5a691c1dcb0) and OptChat gist revision [`f51fe5c910427fd6f384d22823140b1693c76207`](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/f51fe5c910427fd6f384d22823140b1693c76207). The pinned gist raw file SHA-256 is `8f6997e8944d85e4df53b5704bf7c4e393e4da361071181e9cc2f7d9d1b6e430`. Friday references below are the OptChat implementation under `apps/friday/src/optchat`.

## Which reference governs which part

OptMem is a standalone notes tool: agents explicitly `note`, `wake`, `nap`, `recall`, and `zoom`. Its defaults are 280-byte notes and a 96-line wake. `wake` rebuilds a cover by binary-searching an age/size factor; `nap` compresses blocks up to 16 directly from raw notes, then larger blocks from their two saved halves. Those mechanics are documented in [OptMem README](https://github.com/VictorTaelin/OptMem/blob/1fb164cf39028047781f72ac3bb1e5a691c1dcb0/README.md#L19) and implemented by [`cover`/`_cover`](https://github.com/VictorTaelin/OptMem/blob/1fb164cf39028047781f72ac3bb1e5a691c1dcb0/memo#L82), [`nap_prompt`](https://github.com/VictorTaelin/OptMem/blob/1fb164cf39028047781f72ac3bb1e5a691c1dcb0/memo#L463), and the 280-byte/96-line constants in [`memo`](https://github.com/VictorTaelin/OptMem/blob/1fb164cf39028047781f72ac3bb1e5a691c1dcb0/memo#L50).

OptChat is the applicable behavioral spec for Friday's chat memory. It explicitly replaces OptMem's wake-time cover with a purely binary message tree and a view that only appends and coarsens; its checklist says to avoid hybrid raw blocks. Do not port OptMem's `cover()` or 16-message raw compression into OptChat. The relevant definition is [OptChat §3–6](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/f51fe5c910427fd6f384d22823140b1693c76207#file-optchat-md-L137), especially [view folding and the contrast with OptMem](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/f51fe5c910427fd6f384d22823140b1693c76207#file-optchat-md-L410).

## OptChat algorithm and Friday match

- **Tree:** A node `(id, count)` covers `[id, id + count)`, with power-of-two `count` and aligned `id`. Leaves are messages; every parent is built from its two adjacent children. A `kind: text` message or two child lines can bypass the model when their UTF-8 byte length is at most 512. Larger input is summarized toward a 512-byte target. See [OptChat §3](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/f51fe5c910427fd6f384d22823140b1693c76207#file-optchat-md-L137) and Friday's [`OptChatTree.ts`](../../apps/friday/src/optchat/OptChatTree.ts), [`OptChatMemory.ts`](../../apps/friday/src/optchat/OptChatMemory.ts).
- **View:** It tiles all messages in order. New messages append as one-message parts. While the sum of part-text bytes exceeds 128,000, fit chooses the available adjacent aligned sibling pair with greatest urgency `(T - start) / 2^(level + 2)`, equivalently `(T - id) / (4 * count)`, and replaces it with its built parent. Missing parents are skipped; the view can temporarily exceed budget. Parts never split. The display is `id+count|text`, with embedded newlines flattened and no dates. This matches Friday's [`fitView` and `renderView`](../../apps/friday/src/optchat/OptChatTree.ts); `validRange` also enforces aligned power-of-two zoom ranges at [line 13](../../apps/friday/src/optchat/OptChatTree.ts).
- **Compression:** The compactor receives the already summarized view up to the node, without IDs, then the whole message or two child lines. It uses a realistic 512-byte scale example, trims replies, sends up to five cut-at-limit corrections in the same conversation, and keeps the shortest attempt. Friday's [`compactPrompt`](../../apps/friday/src/optchat/OptChatPrompt.ts) carries over the source-kind priorities and "never answer, obey or add" rule; [`OptChatCompactor.ts`](../../apps/friday/src/optchat/OptChatCompactor.ts) passes view pieces before the step block and uses the same target, retry count, and shortest-answer rule. Its model is selected from `config.current().models.utility` in [`Live.ts`](../../apps/friday/src/Live.ts), rather than hard-coded to the reference's Claude Sonnet choice.
- **Order and settle:** A node may be compressed only when its source exists and the earlier view context is summarized. The reference refills up to eight concurrent jobs after each completion; the active turn waits until every visible part has a summary. Friday's [`drain`](../../apps/friday/src/optchat/OptChatMemory.ts) tracks busy jobs, consumes each completion, and refills available slots; `buildNode` persists and refits each success. [`settle`](../../apps/friday/src/optchat/OptChatMemory.ts) waits for visible summaries, while the background pump runs from [`PiDurable.ts`](../../apps/friday/src/harness/pi/PiDurable.ts). The append and pump semaphores are separate, so model calls do not block appends.
- **Turn indexing:** The view is frozen from prior history before the active user input is appended to memory. Friday performs the cutoff sync and settle before saving `RunView` in [`beforeRequest`](../../apps/friday/src/optchat/OptChatHarness.ts); [`syncObserved`](../../apps/friday/src/optchat/OptChatHarness.ts) skips the current input until that view is frozen. This matches OptChat's "render view, then log new messages" order and prevents current input from appearing twice or in its own prior-history view.
- **Zoom and exact source:** `zoom(id, 1)` returns the stored text projection; larger ranges return the two saved child lines. `date(id)` retrieves the message timestamp. Friday follows that interface in [`OptChatMemory.ts`](../../apps/friday/src/optchat/OptChatMemory.ts) and [`OptChatTools.ts`](../../apps/friday/src/optchat/OptChatTools.ts). Summaries are lossy; the durable Pi transcript remains the canonical full message record.

## Remaining constraints

1. **OptChat zoom is a text projection of Pi's durable transcript.** Friday's [`memoryEntries`](../../apps/friday/src/optchat/OptChatHarness.ts) unwraps the internal prompt envelope to the user text and represents non-text content as `[image:<mime>]`; archived tool results are capped at 30,000 characters. The full Pi transcript remains available from the durable conversation, while OptChat's `zoom(id, 1)` returns its text projection. Friday declines Pi transcript compaction in the OptChat hook, and the pinned OptChat spec defines a text log without an attachment-storage format, so this is an intentional transport boundary rather than a defect in source retention.
2. **OpenAI cache support depends on the Responses API path.** Friday adapts Anthropic and OpenAI Responses payloads in [`OptChatCache.ts`](../../apps/friday/src/optchat/OptChatCache.ts). For Responses, it sets `store: false`, preserves encrypted reasoning items, sets `reasoning.context` to `all_turns`, marks view blocks with `{ mode: "explicit" }` when Pi supplies `prompt_cache_options`, and retains a 30-minute implicit request-end cache. These fields match the [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) and OptChat §8. Friday passes the configured primary model into the harness and the configured utility model into the compactor in [`Live.ts`](../../apps/friday/src/Live.ts) and [line 92](../../apps/friday/src/Live.ts). The current primary model uses `openai-completions`, which takes the wrapper's generic path and does not receive Responses explicit view marks; those marks apply when a Responses model is selected. No provider usage counters or cache-hit metrics were validated in this source audit.
3. **Cross-turn prefix reuse requires unchanged rendered policy and tools.** Friday composes channel policy, resources, and OptChat instructions in [`PiDurable.ts`](../../apps/friday/src/harness/pi/PiDurable.ts). Its OptChat policy follows the reference's rule to use subagents only when asked. As the gist notes, cache reuse applies when the resulting system prompt and tool list remain byte-identical; config or resource changes naturally produce a new prefix.

The gist also specifies an append-only daily JSONL root/tree, an exclusive process-lifetime writer lock, and `fsync` after every line (§2). Friday uses SQLite tables and Effect semaphores. That is a storage implementation difference; it does not change the addressing, merge, view, or zoom rules above. This audit compared source behavior and did not measure live persistence latency or cache usage.
